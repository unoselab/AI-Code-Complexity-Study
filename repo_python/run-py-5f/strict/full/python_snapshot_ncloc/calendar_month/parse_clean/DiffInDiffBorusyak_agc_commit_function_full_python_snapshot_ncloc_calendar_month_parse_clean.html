1 Purpose

This notebook runs Borusyak imputation DiD models for Python commit-function AGC outcomes prepared by run-py-5e from the run-py-5d complete table (repo_month_agc_function_event_analysis_complete.csv).

The notebook deliberately separates:

  1. Full repository-month occurrence and count outcomes.
  2. The conditional AGC event ratio among positive-event repository-months.
  3. Paper NCLOC and Python-snapshot NCLOC specifications.
  4. Full and parse-clean samples, selected through PARSE_EXCLUSION_MODE (all keeps every analysis-ready repository-month; parse_clean drops repository-months with has_parse_exclusion == 1).

The two NCLOC variables are never included in the same first-stage formula. Lead/lag columns retained by run-py-5e are validation fields only; dynamic coefficients are requested from didimputation::did_imputation() using horizon = -6:6 and pretrends = -6:-2.

Regression guards carried over from the run-py-5d QC history:

  • Static cohort membership is validated row-by-row from dataset_source against treatment_group and against event-month presence, checked on the full input panel before any filtering. The dynamic is_treatment column is never used for group membership.
  • detection_complete must be entirely true; mixed or missing representations stop the notebook immediately.
  • Zero-event months must satisfy the exact arithmetic has_function_change_event == (function_change_events > 0) and zero_function_event_month == 1 - has_function_change_event.
  • Repository-level dataset_source and adoption month must each be unique per repository.

Guards added for production-run safety (beyond sample construction):

  • TIME_MODE=calendar_month is the primary encoding. original_yyyymm is replication-only and emits a warning, because numeric YYYYMM is not a linear month scale (e.g. 202412 to 202501 differs by 89, not 1), which can distort dynamic event-time horizons at calendar-year boundaries.
  • Under calendar_month, reconstructed time_id - event_id must equal the panel’s own time_to_event on every treatment row used by the models; any mismatch stops the notebook.
  • The final model sample must have unique repo_id + time_id keys, no missing time_id, event_id > 0 for every treatment row, and event_id == 0 for every control row.
  • PARSE_EXCLUSION_MODE=parse_clean must leave zero rows with has_parse_exclusion == 1; otherwise the notebook stops.
  • A final validation chunk turns any static or dynamic model failure, incomplete static estimates, or missing pre-/post-treatment horizon coverage into a hard stop(). tryCatch() around each estimator only isolates one outcome’s failure from the others; it does not by itself guarantee the run produced usable results, so this chunk is what makes a failed run exit with a non-zero shell status instead of rendering a silently incomplete HTML report.

3 Utility Functions

normalize_yyyymm <- function(x) {
  x <- as.character(x)
  x[x %in% c("", "NA", "NaN", "NULL", "None")] <- NA_character_
  x <- gsub("-", "", x)
  suppressWarnings(as.integer(x))
}

yyyymm_to_month_id <- function(x) {
  x <- as.integer(x)
  year <- x %/% 100L
  month <- x %% 100L
  out <- year * 12L + month
  out[is.na(x) | month < 1L | month > 12L] <- NA_integer_
  out
}

require_columns <- function(data, required, label) {
  missing <- setdiff(required, names(data))
  if (length(missing) > 0) {
    stop(label, " missing required columns: ", paste(missing, collapse = ", "))
  }
}

count_nonmissing <- function(data, column_name) {
  if (!(column_name %in% names(data))) {
    return(NA_integer_)
  }
  sum(!is.na(data[[column_name]]))
}

write_error_table <- function(errors, stage, output_path) {
  if (length(errors) == 0) {
    fwrite(
      data.frame(
        stage = character(),
        outcome = character(),
        error = character()
      ),
      output_path
    )
    return(invisible(NULL))
  }

  error_df <- data.frame(
    stage = stage,
    outcome = names(errors),
    error = unlist(errors),
    row.names = NULL,
    stringsAsFactors = FALSE
  )
  fwrite(error_df, output_path)
}
