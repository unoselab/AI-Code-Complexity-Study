지금까지 검증한 것과 별개로, 실제 CSV를 열어보니 **두 가지 실질적 문제**를 발견했습니다. 하나는 예상했던 dtype 문제가 실제로 데이터를 오염시킨 것이고, 다른 하나는 훨씬 더 중요한 문제입니다.

## 🚩 문제 1: `detection_complete` 컬럼이 실제로 오염됐습니다 (경고가 현실화됨)

```
detection_complete value counts: {'1.0': 1289, 'True': 344}
```

지난 turn에서 우려했던 FutureWarning이 단순 경고로 끝나지 않고, **실제로 컬럼에 두 가지 다른 문자열 표현이 섞였습니다.** CSV로 저장되면서 detector-merge된 1,289행은 `"1.0"`(float가 문자열화), zero-event로 채운 344행은 `"True"`(Python bool이 문자열화)가 됐습니다. 이후 누군가 `df["detection_complete"] == True`나 `== 1`로 필터링하면 **절반이 조용히 틀린 결과**를 낼 수 있습니다. 지난 turn에서 드린 수정을 꼭 반영해서 재실행하시길 권합니다.

## 🚩 문제 2: `treatment_group`이 훨씬 더 심각합니다 — 이전에 고쳤던 버그가 재발했습니다

```
treatment_group counts: {'control': 1201, 'treatment': 432}
```

**이 숫자, 어디서 보셨는지 기억하시나요?** 바로 며칠 전 `analyze_agc_commit_function_parse_exclusions.py` **v1의 버그**에서 정확히 이 숫자(`control 1201, treatment 432`)가 나왔었고, 그때 `run-py-3b` 기준 실제 값(`treatment 853 = pre 421 + post 432`, `control 780`)과 대조해서 **"`is_treatment`는 static membership이 아니라 dynamic post_event 값이라 treatment pre-event 421개 row가 잘못 control로 분류됐다"**는 걸 확정하고 v2로 고쳤던 바로 그 버그입니다.

이번 `analyze_agc_zero_event_months.py`가 **같은 함정에 다시 걸렸습니다.** `treatment_column`으로 `is_treatment`(dynamic)를 그대로 쓰고 있고, 그 결과:

* `control: 1201` = 실제 control(780) + treatment pre-event(421) — **잘못 합쳐짐**
* `treatment: 432` = 실제 treatment의 post-event만 — **pre-event 421개가 통째로 빠짐**

## 영향 범위

`by_treatment_period.csv`, `by_event_time.csv` 등 **`treatment_group`을 기준으로 만든 모든 breakdown 파일이 지금 전부 왜곡되어 있을 가능성이 높습니다.** 다행히 `complete` 테이블 자체는 `is_treatment`, `time_to_event`, `post_event`, `event`, `cursor` 원본 컬럼을 그대로 보존하고 있으니(컬럼 목록에서 확인됨), **원본 데이터는 안전**하고 파생 컬럼(`treatment_group`, 그리고 이를 기반으로 만든 groupby 파일들)만 다시 계산하면 됩니다.

## 수정 방향

```python
# The static treatment/control cohort membership must come from dataset_source
# (or the panel's ever_treated column, if present), never from is_treatment,
# which in this project's run-py-4a/run-py-3b panel lineage represents the
# dynamic post-adoption indicator (post_event), not static group membership.
# This exact confusion was already identified and fixed in
# analyze_agc_commit_function_parse_exclusions.py v1 -> v2.
complete["treatment_group"] = complete["dataset_source"].map(
    {"control": "control", "treatment": "treatment"}
)
```

`ever_treated` 컬럼이 panel에 있다면 그걸 써도 되지만, 지금 이 스크립트가 읽는 `run-py-4a` panel에는 `ever_treated`가 없을 수 있으니(이전 확인 시 `is_treatment`/`time_to_event`/`post_event`/`event`/`cursor`만 언급됨) `dataset_source`가 가장 안전한 static 기준입니다.
